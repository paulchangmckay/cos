# Local context guide

Create only the ignored files that help your current work. Record facts supplied by the user, their observation dates, and relevant sources. Keep unknowns explicit. Never fill a new role with facts from a previous employer or from these templates.

For guided setup, say "Help me get started" or invoke the [onboarding skill](../.agents/skills/onboard/SKILL.md) as `$onboard`. It saves useful context as you talk and can resume later. You can also create files directly: start with [self.md](self.md) for role and working preferences, then [priorities.md](priorities.md) for this week's choices. Copy [sources.local.md](sources.local.md) to the repository root only when you want to configure accounts or source access. [project.md](project.md) is a small starting point for an active project under `projects/`.

Use `stakeholders.md` for relationship context, `team/` for durable coaching patterns, and `org/structure.md` for sourced formal reporting and remits. These are distinct records. A reporting line does not establish decision ownership, and one meeting does not establish a lasting coaching pattern.

For `operating-model.md`, start from this loop: validate the problem, make the commitment legible, steer delivery, measure impact, communicate the outcome. Define role-specific mandate, ownership, and decision rights with the user. Keep proposed boundaries separate from accepted ones.

`daily/` holds the journal. `transcripts/` holds original sources and local intake bookkeeping. Neither replaces current project or stakeholder context. See the full file table and writeback rules in [AGENTS.md](../AGENTS.md).
